# Solana.com repository feature map

This map records the requested use of the `solana-foundation/solana-com` repository. LEXI uses its published documentation as a source reference, not as installed code. No Commerce Kit, Headless, Connector, or Solana Pay beta package has been installed. The current Grateful WooCommerce gateway is a separate processor and does not route through LEXI's Solana verifier.

| Solana.com source | Relevant guidance | LEXI implementation relationship |
| --- | --- | --- |
| [Solana Pay v1 specification](https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/tools/solana-pay/specification/version1.mdx) | Transfer URLs carry recipient, amount, token mint, unique reference, label/message, and optionally a public memo; wallets put the reference in a readonly, non-signer instruction account. A memo is public and should contain no private information. | `client/src/pages/Checkout.tsx` creates a USDC URI with amount, official mint, unique per-request reference, label, and order/service text; its wallet transfer instruction includes the reference. The checkout also provides a QR and address/detail-copy fallback. Avoid putting confidential customer information in public payment request fields. |
| [Solana Pay transfer requests](https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/tools/solana-pay/quickstart/transfer-requests.mdx) and [QR codes](https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/tools/solana-pay/quickstart/qr-codes.mdx) | A noninteractive transfer request is distinct from an interactive server-created transaction request. QR codes bridge desktop/mobile wallets; direct wallet/copy fallback supports mobile and accessibility. | LEXI uses a transfer URI and QR, plus Phantom wallet handoff and manual recipient/signature path. It does not claim Solana's newer interactive Transaction Request protocol. |
| [Payment verification tools](https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/payments/accept-payments/verification-tools.mdx) | Never trust the frontend; check network outcome, official mint/program, unique signatures, and actual instruction details. Balance-only parsing can be ambiguous for complex/multi-transfer transactions. Streaming notifications need reconciliation. | `server/payments/solana.ts` queries the RPC, requires finalized successful transaction data, checks the official USDC mint, unique invoice reference, merchant-owned token account, and exact integer delta matching a parsed SPL Token instruction. Durable signature polling/manual reconciliation remain authoritative; no client callback can confirm settlement. |
| [Commerce Kit payment button](https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/tools/commerce-kit/quickstart/payment-button.mdx) and [wallet connection](https://github.com/solana-foundation/solana-com/blob/main/apps/docs/content/docs/en/tools/commerce-kit/quickstart/wallet-connection.mdx) | Commerce Kit presents customizable wallet selection, payment/QR views, and UI callbacks; the documentation describes a beta/draft package. | Used only as a high-level UX reference. LEXI keeps its existing maintained wallet-adapter integration and server verification; it does not add these packages or treat their UI callback as proof of payment. |

## Scope and provenance

The `solana-com` repository is GPL-3.0 licensed. No source code, compiled assets, or dependency from it is copied into LEXI. Detailed cloned-repository/API observations are recorded in [`upstream-feature-notes.md`](./upstream-feature-notes.md). The standard docs references support the existing Solana Pay flow; they do not make Grateful payments Solana transfers verified by LEXI.
